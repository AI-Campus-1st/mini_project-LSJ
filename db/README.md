# DB README

이번 프로젝트는 서울시 지하철 혼잡도와 자치구별 생활인구 데이터를 관리하고 대시보드 성능을 높이기 위해 원본 적재부터 집계 마트까지 이어지는 데이터 아키텍처를 설계했습니다.
데이터베이스는 **MariaDB**를 사용하여 구축했습니다.

---

## 1. 아키텍처 개요
* Collector 모듈이 서울시 열린데이터광장 오픈 API로부터 데이터를 수집·전처리하여 MariaDB에 적재합니다.
* Dashboard는 DB에 접근하여 읽기 전용(Read-Only)으로 데이터를 조회 및 시각화합니다.
* 원본 데이터의 오류 추적성과 대시보드 성능 최적화를 위해 원본(Staging) 테이블과 집계 마트(Mart) 테이블을 분리 설계했습니다.

---

## 2. RAW 계층 (Staging)
서울시 열린데이터광장 API로 수집한 가공 전 원본 데이터입니다.

* **raw_living_pop**: 
  서울시 오픈 API로부터 수집한 자치구별 평균 일일 생활인구 원본 데이터
* **subway_time**: 
  서울시 오픈 API로부터 수집한 지하철 시간대별 승하차 인원 원본 데이터

---

## 3. Mart 계층
원본 데이터를 SQL(`build_mart.sql`)로 집계 및 가공하여, 대시보드가 지연 없이 데이터를 바로 읽을 수 있도록 만든 최종 요약 테이블입니다.

* **mart_region_monthly**: 
  자치구별 생활인구 및 인구 편중 분석을 위한 월별 요약 마트 테이블
* **mart_hourly_profile**: 
  지하철 시간대별 승하차 압박 및 혼잡도 분석을 위한 요약 마트 테이블
